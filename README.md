# DeadScan · 一个命令找出项目里不再有人用的代码

> **npm i -g @hayabusa-yl/deadscan && deadscan** — 两分钟，给代码库做一次全身 CT。

不做 lint，不做类型检查，只审计文件之间的引用关联性。支持 JS/TS/Python/Shell/Ruby/Go/Rust/VBS 等。

---

## 缘起

大肥鱼的项目目录里攒了 675 个脚本，日积月累，谁也说不清哪些还在用、哪些早已失效。手动翻了一遍，揪出 13 个孤儿文件删掉——但删完之后心里没底：删掉的会不会是别的脚本通过动态路径引用的？桥接脚本断了会不会影响上下游？

市面上不缺 lint 工具，缺的是一个**不做类型检查、不做风格纠错、只回答一个问题**的工具——"这个文件还有人用吗？"

DeadScan 就是这么来的。不依赖 webpack，不依赖 TypeScript compiler，一个命令，直接给答案。

---

## 什么是关联性审计

DeadScan 审计的不是语法，是**文件之间的引用关联**：每个文件还有没有任何其他文件在用它。

和常见工具的分工：

| 工具类型 | 回答的问题 | 例子 |
|---|---|---|
| Linter / Type Checker | 代码写错没有？类型对不对？ | ESLint、tsc |
| 依赖循环检查 | 模块之间有没有循环依赖、违规引用？ | madge、dependency-cruiser |
| 未使用导出/依赖检查 | 有没有声明了没用到的 export/依赖？ | knip、unimported |
| **DeadScan** | **这个文件还有没有调用方？** | — |

它跟前面几类不冲突，是补最后一块拼图：语法和类型都过了，但文件是不是已经被所有人忘了——这没人管。

### 三个关键设计

1. **语法解析 + 字符串回退**——import/require/spawn/子进程/模板字符串全扫，解析不到时再用文件名模糊匹配补一刀，动态拼接的引用不漏。
2. **三分类降噪**——孤儿文件分成「动态调用 / 手动工具 / 死代码」，构建脚本、测试辅助、手动跑的工具不会被误判成死代码直接删掉。
3. **零配置、多语言混扫**——不用写配置、不用加标注，十几种扩展名混在一个目录里也能扫。

## 快速开始

```bash
npm i -g @hayabusa-yl/deadscan
deadscan                    # 扫描当前目录，终端输出报告
deadscan --report           # 生成 HTML 可视化报告
```

不用配置文件，不用标注，跑起来就有结果。12 种语言混着放也没问题。

---

## 用法

```bash
deadscan                          # 当前目录
deadscan --dir ~/my-project       # 指定目录
deadscan --json                   # JSON 输出（给 CI/脚本用）
deadscan --report                 # 生成 HTML 健康报告
deadscan --report --output health.html
```

## 它怎么判断

1. **语法解析** — 解析 import/require/调用语句，构建依赖图
2. **字符串回退** — 动态拼接的引用（模板字符串、spawn 参数）用文件名模糊匹配补一刀
3. **分三类**：
   - **动态调用** — 匹配动态模式（`_` 开头、`patch-` 前缀、`lib/` 目录）→ 不算死代码
   - **手动工具** — 文件名含 manual/probe/bench/inspect/debug 等关键词 → 人手动跑的工具
   - **死代码** — 以上都不是，没有引用 → 该处理了

## 真实案例

### axios（57M+ 周下载，10 年历史）

扫描 254 个文件：有调用方 97 个（38% 健康度）。乍看像"一半代码是死的"——看细账：157 个孤儿里 141 个是构建脚本、测试辅助、文档生成器，被归类成手动工具；真正值得处理的死代码只有 1 个 414 字节的沙箱测试文件。

这正是关联性审计要防的事：**健康度分数低不等于代码烂**，三分类先把"没人 import 但人在用"的文件摘出去，结论才可信。

完整记录见 [case-studies/axios.md](case-studies/axios.md)。

### 作者自己的项目

675 个脚本混在同一个目录，日积月累没人记得哪些还在用。DeadScan 一次扫出 13 个孤儿文件——省掉的不是删文件的时间，是删之前逐个确认"真的没人调用吗"的纠结。

## 配置文件（可选）

项目根目录放 `.deadscanrc.json`：

```json
{
  "skipDirs": ["vendor", "generated"],
  "skipPrefixes": [".", "_", "legacy-"],
  "extensions": [".mjs", ".js", ".ts", ".py"],
  "maxDepth": 30,
  "dynamicPatterns": ["^_", "^patch-.*\\.mjs$"],
  "manualKeywords": ["manual", "probe", "bench"]
}
```

## HTML 报告

`--report` 生成独立 HTML 文件，含健康度环形评分、死代码清单（路径/大小/最后修改时间）、活跃文件调用关系、五维统计。
